# CommandCenter

相机 + PLC 现场命令中心上位机（.NET Framework 4.7.2 WinForms）。

上位机作为命令中心，按"扫码得 SN → 相机拍照 → 保存图片 → 显示在对应点位窗口 → 上报结果给 PLC →
走下一工位"的节奏运转，同时负责操作员交互（切换产品型号、SN 录入、查看来料）。

> 完整业务流与寄存器表见 **`docs/CommandCenter.md`**（第二部分/第五部分）
> （V2.7 定稿：`40001~40011`"请求-结果-复位"三拍握手，PLC 写请求→上位机写结果→PLC 复位请求→
> 上位机复位结果）。`ProductionCoordinator` 实现三通道状态机（通道①扫码、通道②上相机、通道③下相机），
> 每次扫码完成自动把固定产品型号（`productModel`）写入 PLC 40007~40011。

## 技术栈

- .NET Framework 4.7.2 WinForms（C# 7.3）
- NModbus 3.0.83 —— 汇川 PLC Modbus TCP 通讯（本地 `libs/` 引用，离线可编译）
- Newtonsoft.Json —— 配置/型号序列化（本地 `libs/` 引用）
- 相机：基恩士 IV4-500CA，TCP/IP 无协议通信触发拍摄（T1/T2/RT，V1.12.18 加 PW 切程序/OF 输出格式），
  取图走 FTP 推图（jpeg+iv4p 双文件归档；**文件名任意编号非 0000，V1.12.24 起扫取图目录取修改时间
  最新的一对**，V1.12.18 起唯一取图方式，Tcp/BR 已下线）

## 可配置项

所有参数集中在运行时生成的 `Config/appconfig.json`：

- 相机：**两台相机列表**（V1.12.22 现场默认；V2.13.3 修正 FTP 目录——上/下相机的取图目录与安装
   位置相反配对：列表第1台=**上相机** `19.87.6.213`→FTP 取图目录 `D:\IV存图\2`、列表第2台=**下相机**
   `19.87.6.212`→`D:\IV存图\1`，字段 `name`/`cameraId`/`ftpUploadDir`；
   每台另含触发端口、触发指令、超时、取图方式、点位→程序号映射表；配置文件缺失或留空时自动用这两台），
   一次"到位"对所有相机**并行触发**拍照（V1.8.3 起，总耗时 ≈ 最慢一台相机，节拍快不漏检）。
  **相机编号（V2.13.4）**：`cameraId`=基恩士相机真正编号、与存图目录号一致（上=2、下=1）；
   独立存字段、**不靠交换列表顺序**，设置页相机表第一列即"相机ID"，`0`=按行序兜底。
  **PLC 相机通道（V2.13.5 显式配置）**：每台相机一路请求/结果通道，地址独立存
   `plcRequestAddress`/`plcResultAddress`（默认上=2/5=协议40002/40005、下=3/6=协议40003/40006，
   **0=未配置通道、不参与轮询**），列表顺序不再决定任何通道地址，新增相机须显式填地址。
  **取图方式（V1.12.18 起仅 `Ftp`，Tcp 下线）**：相机作 FTP 客户端推图到 `D:\IV存图\1/2`
   （目录由相机侧配置，上位机按 `ftpUploadDir` 监听取图），上位机 FileSystemWatcher 监听新图；
   Tcp/BR 直读代码保留仅作旧配置兼容，设置窗体不再提供该选项。
  **点位→相机程序号（V1.12.25 起按相机分表；V1.12.26 起下拉选择、支持任意台相机；V2.8 起按产品型号
   再分表）**：现场"28 个窗口点位由两台相机分工拍摄"（不是每台相机都拍全部点位），各相机程序库互相
   独立，所以映射是**每台相机一张表** `stationPrograms`（`[{stationNo,programNo},…]`，表里配了哪些
   点位=这台相机负责拍哪些点位）。**同一台相机的映射还随产品型号变化**：`modelStationPrograms`
   （`[{modelName:"U171",programs:[{stationNo,programNo},…]},…]`）按型号各建一张表，运行时按当前
   产品型号查对应型号的表切程序，型号没配表就回退 `stationPrograms` 默认表。触发前按本轮点位查表：
   命中先发 `PW,nnn` 切到该点位程序再触发、**未命中不切换**（旧固定 `ProgramNo` 字段 V1.12.25 起
   废弃、仅旧配置兼容）。   设置入口与"窗口↔相机点位"矩阵**同页混排在"窗口/点位配置…"对话框**
   （**相机下拉 + 型号下拉**（V2.12.4 起型号下拉只列真实产品型号、"默认"项已移除）+ **点位/程序号
   两列下拉选择**——**点位列=窗口映射点位**（数量=窗口数；V2.13 起矩阵可编辑：编辑点位/交换位置/
   恢复默认，结果按型号存 `display.windowPointMaps`，见下"显示"节）、**程序号列="不切换"
   +0~127（0 合法，"不切换"=保持相机当前程序；程序数量和具体编号按相机程序库动态配、与窗口数无关）**；
   **新增相机（设置表加一行）自动有自己的空表**，配好点保存映射不丢）。
   存图文件名默认追加时间戳后缀（`FileTimestampSuffix`）防同点位重复触发覆盖。
- PLC（**V2.7 协议**，上位机做从站监听 502、现场汇川 PLC 做主站 TCP 连入）：监听绑定 IP
  （`0.0.0.0`=所有网卡）、监听端口、从站 UnitId、**V2.7 握手寄存器地址**（扫码/上相机/下相机请求
  `40001~40003`、扫码/上/下相机结果 `40004~40006`、产品型号 `40007~40011`）。流程为**"请求-结果-复位"
  三拍握手**：PLC 写请求≠0 → 上位机处理完写结果≠0 → PLC 读走并复位请求=0 → 上位机看请求清零再复位
   结果=0。寄存器地址全部收进 `appconfig.json` 的 `plc` 节点（**统一存 DataStore 索引，
   PLC 协议号 = 索引 + 40000**：协议 40002 上相机请求 → 配置填 2，业务层零换算，
   填 2 就是 D2，V2.12.3 已删除协议号换算），现场只改 json；
   完整协议见 `docs/CommandCenter.md` §5.5。
- **固定产品型号（V2.7；V2.8 起多型号候选 + 主界面直接切换）**：顶部 `productModel`（当前型号，
  **默认 "U171"**——V2.12.3 起非空默认，无配置文件首次启动也按该型号点位表铺窗，不再塌成 1 个窗口）
  + **候选列表 `productModels`**（默认 `["U171","U172","Z121"]`，可手输新型号自动加入）。每次扫码完成
  上位机自动把 `productModel` 写入 PLC `40007~40011`（最多 10 个 ASCII 字符、每寄存器 2 字符、不足补
  `0x00`、超长截断）。**型号同时决定"点位→相机程序号"查哪张表**（见相机映射的 `modelStationPrograms`）
  ——现场切型号有两条路：① 设置窗体 PLC 区"产品型号"可编辑下拉（保存热更生效）；② **主界面标题栏
  型号下拉 `cmbModel`**（V2.8，候选恒预置 U171/U172/Z121，配置缺字段也能直接选），选完**立即生效**
  （重建协调器按新型号查映射、设备不断连）并写盘持久化。两处是同一个 `productModel` 值。
- 显示：窗口行数 × 列数、标题栏字段开关、OK/NG 颜色名、**窗口↔相机点位 + 点位→相机程序号**
  （同一"窗口/点位配置..."对话框：上区格子矩阵随**型号**联动展示"归属相机·点位号"，
  **V2.13 起可编辑**（编辑点位/交换位置/恢复默认，结果按型号存 `display.windowPointMaps`
= `[{modelName, points:[{cameraIndex,stationNo},…]}]`，默认=前上相机后下相机铺排、不编辑行为
   与旧版一致；编辑点位候选=相机点位表已有点位且自动排除已被其他窗口占用的组合、交换位置可互换
   任意两窗口（**含跨相机**，V2.13.1 放开——交换的是"窗口↔（归属相机,点位）"对应，不改相机自身
   点位/程序映射；不同相机同号点位不是同一个，靠归属相机·点位号二元组区分）、恢复默认=重置该型号
   铺排并全部启用），下区"相机程序映射"按"相机+型号"
  配"点位↔程序号"，V1.12.25 每相机一张表、V2.8 起按产品型号分表、型号占候选 U171/U172/Z121），
  **显示窗口矩阵"自适应"开关（`DisplayConfig.AutoFit`，V2.12.0 引入，JSON `autoFit`，默认 false；
  V2.12.1 统一模型：窗口总数**恒**=各相机按当前型号点位表条目和，自适应勾选只决定行列是否自动算
  （勾选后行/列输入框置灰自动铺排，列=min(7,总数)、行=ceil(总数/列)、点数≤7 单行铺满；不勾时手填
  行列当"排列宽度"，放不下自动补行，两种模式所见一致）；换型号自动重排），
  **标题栏 OK/NG 色块高亮开关**（`TitleOkNgHighlight`，在设置窗体"OK/NG显示"行配置），
   **窗口右下角 OK/NG 徽标显隐开关**（`WindowOkNgVisible`，V2.10.3，默认 false；勾选"窗口徽标"后
   主界面每个显示窗口右下角叠加自绘矩形框 OK/NG，颜色随 OK/NG 颜色名配置），
   **窗口左上角窗口编号显隐开关**（`WindowIndexVisible`，V2.10.6，默认 true；取消勾选"显示窗口编号"
   后主界面每格左上角不再显示窗口编号，画面更干净。开关在设置窗体"窗口点位"行"窗口/点位配置..."按钮
   右侧）、
   **窗口悬停气泡提示显隐开关**（`WindowToolTipVisible`，V2.10.8，默认 true；取消勾选"悬停提示"后
   鼠标放到显示窗口上不再弹出"双击放大/还原"气泡，开关位于"显示窗口编号"右侧），
  **标题栏"系统设置"按钮显隐开关**（`ShowSettingsButton`，默认 true；生产现场写 false
  可隐藏按钮防误操作，布局自动紧凑，改回只需改 json）
- 图像：保存根目录、**存图目录结构**（可视化逐级配置，默认 年月日/SN号/**相机**/OK|NG，点位号进文件名，
  在设置窗体点"配置目录结构..."编辑。**V2.12.1 起存图点位=相机点位号**（上下相机各自从 1 起会重复），
  默认含 **`{相机}` 目录层**把两台相机隔开，旧配置加载自动补这层，只有一台相机可删）、FTP 监听目录。
  ⚠️ **FTP 取图上位机零配置（现场确认）**：FTP 推图由基恩士工程师在相机软件（IV Navigator）里
  配置好，上位机**无需部署/安装任何 FTP 服务器**（FileZilla 等一概不用），程序只监听推图落盘目录
  （FileSystemWatcher）；图不到先联系基恩士核对相机侧推图。
  **双文件归档（V1.12.18；V1.12.24 取图扫目录取最新）**：基恩士每次拍照生成 jpeg+iv4p 两个文件
  （**文件名不保证是 0000**，可能是 0084 等任意编号），程序按扩展名配对、都到齐才算图到位
  （事件只作信号加速），归档时**自动扫该相机 FTP 目录取修改时间最新的一对**，**归档到正式目录后
  删除实际归档的 FTP 源文件**（FTP 目录只当中转暂存区，处理即删）；
  iv4p 为基恩士私有复盘格式、原样复制保留，jpeg 为显示/归档主体。
  **存图重名防覆盖（V1.8.3）**：同 SN/判定目录里同点位二次拍照自动追加 `_2/_3…` 序号；
  **V1.12.18 起文件名另加时间戳后缀**（`FileTimestampSuffix`）双保险，不丢历史图。
- 扫码枪：**多台扫码枪列表**（每台：启用开关、方式 串口/以太网无协议 Tcp、串口参数、
  IP/端口、**触发指令**），设置窗体"扫码枪列表"可视化增删改；任何一台扫到的条码更新当前序列号
  （按项目约定：停止位存 "1"/"15"/"2"，校验位存标准枚举名）。**V1.12.8 起 TCP 与串口拆为两张表**
  （`gridScannersTcp` / `gridScannersSerial`）：TCP 表只配 IP/端口/触发指令，串口表只配串口名/波特率/
  停止位/校验位，方式由"所在的表"决定、不再有"方式"下拉列——解决同一张表行间切 Tcp/Serial 导致
  整列显隐混乱的 bug。两张表各带一行默认值（TCP=19.87.6.100:9004/LON，串口=COM3/115200/1/None），
  打开即可直接改。**V1.12.9 起 TCP 表默认行与"添加一台"默认勾选"启用"**（与代码默认接入的
  以太网扫码枪一致——主程序对 Mode=Tcp 建 `ScannerTcpService`，连上即发 `LON` 自动收码）；
  串口表默认行不勾选（代码默认不用串口枪，要接入再手动勾）。内容超出窗体高度时右侧自动出竖滚动条，
  保存/取消固定底部不随滚动。
  **触发指令（V1.12.1，仅 Tcp 模式）**：基恩士 SR 无协议模式下上位机连上后需先发一条
  `TriggerCommand`（默认 `LON`，发送时自动补 `\r\n` 帧结束符）扫码枪才进入读码状态；
  每次连接/断线重连后自动发送，留空则不发送（对应扫码枪设成"上电自动读码"模式）。
  默认地址为现场实测 `19.87.6.100:9004`。
- 管理员：**登录开关**（`Security.AdminEnabled`，默认 true）、用户名（`AdminUser`，默认
  `admin`）、密码 **SHA-256 哈希**（`AdminPasswordHash`，不存明文；默认出厂密码 `admin123`）。
  启用后点"系统设置"每次都要登录管理员账号才放行；改密码在**登录对话框**里完成（登录界面
  自带"修改密码"入口：验证原密码 → 新密码两次一致且 ≥6 位 → 保存即时生效），系统设置窗体
  保持纯业务配置不掺账号管理。另提供**"记住密码"**勾选框：勾选后登录成功把用户名+密码用
   Windows DPAPI 加密存到 `%LOCALAPPDATA%\CommandCenter\`（绑定当前
   Windows 用户，拷走文件也解不开），下次打开登录框自动回填、点登录即可；取消勾选或改密码
   时自动清理/同步。**V1.12.21：开发者账号也可记住密码**（存 `remembered_login_dev.dat`，
   管理员存 `remembered_login.dat`），且两角色记录**互斥**——登录任一方成功即清除另一方的
   记住文件，避免跨角色回填残留（管理员登录后不再保留 dev 免密入口，反之亦然）。
- **开发者账号（V1.12.0，功能测试登录）**：`Security.DevEnabled`（默认 true）、
  `DevUser`（默认 `dev`）、`DevPasswordHash`（默认出厂密码 `dev123` 的哈希）。
  用开发者账号登录"系统设置"按钮后，进的是**功能测试窗体 `DevTestForm`** 而不是系统设置：
只做 PLC/相机/扫码枪通讯手动验证（相机 T1 仅触发 / T2 触发+读判定、扫码枪读码实时展示、
   PLC 读地址/写地址测试 + 协议偏移量配置 + V2.7 读请求/写产品型号/写结果信号），**复用主窗体已建好的
   连接、不新建连接、不产生配置改动**；开发者密码不支持在登录框里改（改密码面板仅服务管理员），
  改哈希需手动算后写配置。
  典型场景：PLC 业务逻辑未写完时，用 dev/dev123 单独验证相机、扫码枪与 PLC 通讯链路是否通。

换机型/切型号现场只改 JSON，复用同一份程序；产品型号映射与相机程序映射优先走界面下拉（设置页），
不手改 json。
