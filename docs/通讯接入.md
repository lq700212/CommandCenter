# 通讯接入说明（CommandCenter）

> 本文档记录 CommandCenter 与外围设备的通讯对接方式，改动通讯类内容必须同步更新本文件，并写明版本号。

## 一、总览

| 设备 | 厂家/型号 | 通讯方式 | 协议 |
| --- | --- | --- | --- |
| 智能相机 | 基恩士 IV4-500CA | TCP/IP 无协议通信（×2 连接） | ASCII 指令 + FTP 图像上传 / BR 图像读取（V1.7.0 二选一） |
| PLC | 汇川 | Modbus TCP（从站） | Modbus 保持寄存器 |
| 扫码枪 | 基恩士 SR 系列 | 串口 RS-232 / 以太网 TCP/IP 无协议（V1.8.0 二选一） | 条码文本行 |

## 二、扫码枪（基恩士 SR 系列，V1.8.0）

> 客户确认扫码枪也是基恩士的。SR 系列支持串口 RS-232 与以太网 TCP/IP 无协议两种
> 通讯（无协议方式与 IV4 相机同思路：上位机作 TCP 客户端）。本程序两种都支持，
> 在 `appconfig.json` 的 `scanners` 列表里用 `mode` 二选一（V1.8.1 起为列表）。

### 1.1 配置（appconfig.json → scanners，V1.8.1 起为列表，支持多台）

```json
"scanners": [
  {
    "enabled": true,
    "mode": "Tcp",           // "Tcp"=基恩士以太网无协议（上位机作客户端收条码行）；"Serial"=串口
    "ipAddress": "19.87.6.100",  // 现场实测默认，可按现场改
    "port": 9004,            // 基恩士 SR 无协议监听端口，现场实测默认
    "triggerCommand": "LON", // V1.12.1 触发指令：Tcp 连上后自动发送并补 \r\n，扫码枪才读码；留空不发
    "portName": "COM3",      // 仅 Serial 模式
    "baudRate": 115200,
    "stopBits": "1",
    "parity": "None"
  }
]
```

> 多台：列表加一行即可（不同工位/不同门各一把）；任何一台扫到的条码都会更新当前
> 序列号（标题栏 + 存图 {SN} 目录同步）。设置窗体"扫码枪列表"表格可可视化增删改，
> 与相机表格同风格，`enabled` 不打勾则该台不接入。

### 1.2 Tcp 模式（ScannerTcpService，V1.12.1）

- 上位机作 **TCP 客户端**连扫码枪（`ipAddress:port`），**连接成功后自动发送触发指令**
  `triggerCommand`（默认 `LON`，帧尾补 `\r\n`）——基恩士 SR 无协议模式**不是连上就回数据**，
  多数机型需先发"打开激光/开始读取"指令才进入读码状态（现场实测）；
  断线自动重连后也会再次发送，扫码枪始终处于可读状态；
- 之后扫码枪读到条码后把条码文本（通常 + CR/LF）**主动推送**给连接方，与串口行为一致，
  按行切分，一行=一条码；
- 后台线程：连接 `BeginConnect+WaitOne` 强制超时（2s）→ 发送触发指令 → 阻塞读流按行收码；
  断线按 3s 节流**静默自动重连**，连上即恢复，不打扰主流程；
- ⚠️ **扫码枪只接受一个 TCP 客户端（V1.12.5 现场实测确认）**：用网络调试助手/其他工具占着连接时，
  上位机连上即被踢或拒绝，表现为"一直断连"。调试助手测完必须**关闭连接**再重启本程序。
  看日志区分两种情况：
  - `扫码枪(TCP)连接失败（后台持续重连）` → 一直没连上，多半端口占用/地址不对；
  - `扫码枪(TCP)连接断开，3s 节流后自动重连` → 已连上又被踢，检查是否被调试助手等占用。
- 功能测试窗体（DevTestForm）提供"发送触发指令"按钮可手动重发 LON；
  扫码枪状态灯随真实连接实时变色（绿=已连接/红=断连，V1.12.5 起订阅 `IScanner.ConnectionChanged`）；
- 扫到的条码 → `ProductionCoordinator.LatestSerialNumber`（进标题栏"序列号:"与存图 {SN} 目录）。

### 1.3 Serial 模式（ScannerService）

- 监听 `portName` 串口 DataReceived，按 CR/LF 切行，一行=一条码；串口打不开不影响主流程。

### 1.4 现场校准清单

- [ ] **确认扫码枪无协议模式的监听端口与触发指令**：默认 `19.87.6.100:9004 / LON` 为现场实测值，
      换场地换扫码枪仍要实测确认（触发指令可能是其它值，改 `scanners[].triggerCommand` 即可，不用改代码）
- [ ] 扫码枪设成 TCP 服务器（无协议）模式，确认监听端口与 `scanners[].port` 一致
- [ ] 程序日志出现 `扫码枪(TCP)已连接` + `扫码枪(TCP)触发指令已发送：LON`，扫码枪激光应打开开始读码
- [ ] 用网络调试工具连扫码枪扫一下，确认收到"条码 + CR/LF"文本行（若有头/尾附加字符，
      按实测在 `ScannerTcpService.ReadLoop` 的切行逻辑里处理）
- [ ] 程序日志出现 `扫码枪收到条码：xxx` 且标题栏"序列号:"随之更新
- [ ] 断线（拔网线/重启扫码枪）后 3~5s 内自动重连，日志出现 `扫码枪(TCP)已连接`，重连后触发指令自动重发
- [ ] ⚠️ **调试助手占用排查（V1.12.5）**：扫码枪只接受一个 TCP 客户端，用调试助手测试时
      必须先**关闭调试助手的连接**再测本程序，否则程序表现为持续断连（日志出现"连接失败"或
      "连接断开"两种形态，见 1.2 说明）
- [ ] ⚠️ **扫码枪配置务必在"系统设置→扫码枪列表"里填**（V1.8.1 起配置是 `scanners` 数组），
      手改 json 里旧版单对象 `scan` 段不会生效（会被忽略，扫码枪不会启动）

## 三、相机（基恩士 IV4-500CA）

### 2.1 硬件能力

IV4 系列内置以太网，支持：EtherNet/IP、PROFINET CC-B、**TCP/IP 无协议通信**（最多 2 路连接）、FTP/SFTP 客户端、SNTP、OPC UA 服务器、MQTT 客户端。(来源：基恩士官网 IV4-500CA 规格页)

### 2.2 对接方式（V1.0.1，V1.7.0 增加 TCP 直读取图）

上位机作为 TCP 客户端，连接相机 `CommandPort`（默认 8500，可改）。指令均为 ASCII 文本，
正文以 **CR（`\r`，0x0D）** 结束（相机回帧则以 CR 或 CRLF 结束，程序两者兼容）。

1. **触发拍摄（T1）**：发送 `CameraConfig.TriggerCommand`（默认 `T1`）。相机仅执行拍摄，
   不返回判定，适合"只拍不断判、判定交给别的设备"的场景。
   **CR 语义**：发送 `T1[CR]`（程序自动补 `\r`），相机收到后回显 `T1[CR]` 作为确认帧——
   CR（回车符 `\r`）是数据包结束标记，双方靠它识别帧边界。程序只需确认收到回显
   （`SendTrigger` 返回 `raw != null`）即视为触发成功，不解析回显内容。
2. **触发拍摄 + 读取判定（T2，本程序默认走这条）**：发送 `CameraConfig.TriggerAndReadCommand`
   （默认 `T2`）。相机拍摄后**直接返回最新一次判定结果**，一次通讯完成"触发 + 拿结论"，
   与现场"拍照即得 OK/NG"要求一致。响应例：`RT,00000000`（读实型/判定结果，见下）。
3. **单独读取判定（RT）**：在已有拍摄结果的前提下，发送 `CameraConfig.ReadResultCommand`
   （默认 `RT`）只读最近一次判定，支持"先 T1 触发、稍后再取结论"的异步节拍。
4. **判定响应格式**：`RT,xxxxxxxx` —— 逗号后为"标准结果"8 位字符，**每位对应一个工具**
   （工具顺序由 IV4 流程配置决定）：`0`=OK、`1`=NG、`4`=未进行、`-`=工具未启用。
   本程序判定规则（`KeyenceIV4Camera.ParseResult`）：
   - 全部判定位为 `0`（合格位）→ OK；
   - 存在 `1` 或任何非合格位（`4`/`-`/未知字符）→ 保守判 NG；
   - 结果为空、响应缺 RT 前缀、超时/断连 → 本次通讯失败，走 Done=2。
5. **读取最新图像（BR，V1.7.0 新增，Tcp 取图模式）**：指令 `BR,m[CR]`（m=压缩率，见
   `CameraConfig.ReadImageMode`；`0`=无压缩，`1`=1/2 压缩）。响应：
   ```
   BR,nnnnnnnnnn,ddddddd,<图像数据>
   ```
   - `nnnnnnnnnn`：**合计触发编号**（10 位十进制；通过计数模式时固定为 999999999，
     一般模式为 0~DWORD_MAX-1）；
   - `ddddddd`：**图像数据的数据长度**（真正决定后面要读多少字节的字段）；
   - 逗号后紧跟**二进制**图像数据（24bit 位图，期望为完整 BMP 文件，即 `BM` 文件头 + 像素）。
   > **V1.9.1 修正**：此前版本把"合计触发编号"误当成图像字节数、把"数据长度"当成属性，
   > 正好颠倒导致按触发编号读图失败。现按手册顺序"触发编号 → 数据长度"重新解析，
   > 触发编号仅透出日志对照。
   解析要点（`KeyenceIV4Camera.ReadImage`）：图像数据是二进制、可能含任意字节（含 0x0D/0x0A），
   必须先用状态机精确读完 ASCII 头部，再按长度字段精确读 N 字节，不能按"读一行"处理。
   > **无最新图像时报错**：手册说明"在没有最新图像的状态下试图读取"会出错，此时响应不是
   > 正常 `BR,...` 帧（可能断连/回错误码），前缀校验不过即判失败并走断连重连。
6. **图像回传（两种取图来源二选一，V1.7.0）**：每台相机在 `CameraConfig.ImageSource` 里独立选择：
   - **Ftp（默认，成熟）**：在 IV4 Navigator 里把相机配成 FTP 客户端，推图到上位机监听目录。
     **多相机（V1.1.0）**：每台相机的 FTP 上传目录独立配置（`CameraConfig.FtpUploadDir`，
     为空则回退全局 `ImageConfig.FtpRootDir`）——多台务必分开，否则新图归属无法区分。
     上位机为每台相机各建一个 `FileSystemWatcher`，新图事件带相机索引。
   - **Tcp（V1.7.0 新增）**：上位机在 T2/T1 触发成功后，同一连接上紧接发 `BR,m` 指令
     同步读回相机最新图像（无需 FTP 服务器落盘中转）。Tcp 模式该相机不注册 FTP 监听。
   现场二选一实测后定；两种模式下图的归档（目录结构/文件名模板）与显示逻辑完全一致。
7. 断线处理：TCP 连接 `BeginConnect+WaitOne` 强制超时，失败自动重连；
   图片等待有 `ImageWaitMs`（默认 10s）兜底超时（Tcp 模式为同步取图，基本不靠它）。
   指令正文与换行符均可在 `appconfig.json` 的 `cameras` 数组节点分别修改。

### 2.2a 多相机配置（V1.1.0）

- 相机配置是 `cameras` **数组**，配置里列几台就触发几台；项目未上线，
  不做旧配置迁移：`appconfig.json` 缺字段一律用模型默认值。
- **现场默认两台相机（V1.9.8 定稿）**：图 IP 已写死，相机1=`19.87.6.212`、相机2=`19.87.6.213`。
  无配置/空配置时程序自动用这两台（`CameraConfig.DefaultCameras()`），设置窗体表格默认
  也带这两行；现场换相机 IP 只需改那一处工厂方法（或设置窗体改 IP 后保存）。
- 一次"到位"信号 → 对所有相机**并行触发**一次（T2，V1.8.3 起多相机并行，每台一个任务，
  总耗时 ≈ 最慢一台相机，避免串行累加在节拍快时漏检），每台各自记录判定/结果；
  各 FTP 新图**到齐后**整体收尾，每张图一个 `WindowData` 提交、环形刷新显示窗口。
- 存图点位由 **`DisplayConfig.WindowStationMap`（窗口→点位映射）** 驱动（V1.3.0）：
  默认"点位=窗口编号"（1 号窗口存 1.png），可在设置窗体"窗口/点位配置…"里可视化自定义/交换；
  相机配置不再含点位字段。
- 标题栏连接指示灯按相机台数动态显示：`●PLC`、`●相机1…●相机N` 依次排布，断连变红。

## 四、PLC（汇川）

### 3.1 硬件与配置

- 汇川 PLC 开启 **Modbus TCP 服务器**，端口 502，IP 静态（如 192.168.1.10）。
- D 寄存器映射到 Modbus 保持寄存器区：D0→40001、D100→40101……（Modbus 绝对地址 = 40001 + D地址）。
  NModbus 的 `ReadHoldingRegisters(start, count)` 起始地址即 D 地址，库内已按功能码 03 处理，**无需换算**。

### 3.2 寄存器表（V1.0.0 约定，与现场 PLC 程序核对后调整）

| 功能 | D 地址 | 方向 | 类型 | 说明 |
| --- | --- | --- | --- | --- |
| 相机到位信号 | D100 | PLC→上位机 | Word(0/1) | 位 1 表示到位；上位机读到后写 0 复位 |
| 开始信号 | D101 | 上位机→PLC | Word(0/1) | 触发一次检测的启动 |
| 完成信号 | D102 | 上位机→PLC | Word | 1=拍照成功，2=取像失败，0=复位 |
| 配方号 | D103~D107 | 上位机→PLC | 字(ASCII) | 每寄存器 2 字符，其余补空格；长度=RecipeLen |
| 检测总数 | D110 | 上位机→PLC | Word | 计数热备，PLC 侧可用作节拍统计 |
| OK 数 | D111 | 上位机→PLC | Word | 同上 |
| NG 数 | D112 | 上位机→PLC | Word | 同上 |

> 寄存器地址全部收进 `Config/appconfig.json` 的 `plc` 节点，现场只改 JSON 不必动程序。

### 3.3 握手时序（与现场动作一致）

```
PLC 传到上位的记录             上位机
    (D100=1) 相机运动到位 ──>  Detected
                 <─────────── 触发相机拍照 (TCP "T2" → 触发+读判定)
                              （判定 OK/NG 来自相机回帧；图仍未到前流程不结束）
                 <─────────── 等图（FTP 新图，超时 ImageWaitMs 记取像失败）
                 <─────────── D102=1 通知完成 / D102=2 取像异常
    (D100=0) 机构去下一点位
```

## 五、计数与结果流转

- 结果来源（V1.0.1 起）：**相机判定返回值**为准（T2 回帧标准结果，全 0 → 记 OK，含非合格位 → 记 NG）；
  取像是否成功（FTP 新图是否到达）只决定 `D102` 写 1 还是 2，**不再决定 OK/NG**。
  未在配置开启 `ReadResultFromCamera` 时退化为旧逻辑：FTP 图到即记 OK。
- 上位机按"最近 N 次环形"刷新显示窗口：每完成一次检测把结果写进下一个窗口（1..Rows×Columns 循环）。
- 标题栏统计（总数/OK/NG）本地累计，并同步写回 PLC 三个计数寄存器。
- **存图目录结构（V1.2.0）**：默认结构 = 根目录 / 年月日(2026年08月11日) / SN号 / OK|NG / 点位号.png。
   目录层级由 `ImageConfig.SubDirs` 列表逐级驱动（每级一个目录名或生成规则），文件名由
   `FileNameTemplate`（默认 `{点位}`）生成，支持占位符 `{年月日}{年}{月}{日}{SN}{OKNG}{点位}{时间}`，
   其余文字原样保留；`{年月日}` 是【一个】目录名（如"2026年08月11日"），不是年/月/日三级。
  可视化配置入口：设置窗体 → "配置目录结构..."（DirTreeEditForm，可增删移层级 + 实时预览 OK/NG 路径）。
  SubDirs 为空时用模型默认三层 `{年月日}/{SN}/{OKNG}` 兜底（V1.3.0 起不再保留旧模板回退）。
  SN 通过扫码枪/手动输入写入每次检测的 SerialNumber。
