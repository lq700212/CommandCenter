# 第一部分 用户使用说明（操作员手册）

> 适用人群：现场操作员 / 班组长 / 设备维护工程师。
> 本文只讲"怎么用"，不谈内部实现；通讯/寄存器/指令等对接细节见本文档第二~五部分。

<a name="part1-s1"></a>
## 一、软件启动

1. 双击 `CommandCenter.exe`（或桌面快捷方式）启动。
2. 启动即自动铺满屏幕工作区（保留任务栏，不是全屏独占；边框固定不可拖拽缩放，
   最小化 / 关闭按钮正常可用）。
3. 无需登录即可观看主界面；只有点 **"系统设置"** 按钮时才需要登录（见 §四）。

启动失败排查：先看 `Logs/` 目录当日日志，进程起不来的常见原因是 `Config/appconfig.json`
被手改坏（JSON 语法错误 / 字段类型错），删除或修正该文件后重启。

<a name="part1-s2"></a>
## 二、主界面速览

```
┌──────────────────────────────────────────────────────────────────┐
│ 产品型号:[型号▾]  序列号: [框·点击即录]  总数:0  OK:0  NG:0   [系统设置]  ●PLC●扫码枪●相机1●相机2│
├──────────────────────────────────────────────────────────────────┤
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                    │
│  │  W1  │ │  W2  │ │  W3  │ │  W4  │ │  W5  │   ← 窗口矩阵       │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────┘      （行列数按配置）│
├──────────────────────────────────────────────────────────────────┤
│ 状态: 等待PLC主站到位信号…                                        │
└──────────────────────────────────────────────────────────────────┘
```

- **标题栏**：产品型号（V2.8 下拉，可直接切型号）→ 序列号 → 总数 / OK / NG 计数
  → 系统设置按钮 → 连接指示灯。
  - 计数默认是"实心彩色块 + 白字"（绿底=OK、红底=NG），醒目且符合现场习惯。
  - 连接指示灯从右到左：相机… → 扫码枪 → PLC。绿=已连接、红=断连/故障。
    PLC 灯三态：**绿**=主站已连入、**黄**=监听就绪等主站、**红**=监听失败（鼠标悬停有排查提示）。
  - 各字段可按配置开关显隐（标题栏更紧凑），现场不需要的字段可让管理员在设置里关掉。
- **窗口矩阵**：每格一路画面，检测完成后逐格环形刷新最新图片；绿色/红色已不再叠加显示
  在画面上，判定结果看标题栏计数与存图目录（OK/NG 子目录）。
- **底部状态栏**：显示流程当前阶段（等扫码到位 / 等相机到位 / 拍照中 / 型号切换完成等）。

<a name="part1-s3"></a>
## 三、日常操作

### 3.1 切换产品型号
- 直接点标题栏的**产品型号下拉框**（V2.8），候选预置 `U171/U172/Z121`（也可在系统设置里加新型号），
  选目标型号即切换。
- 切换后状态栏变绿显示"型号切换完成"，**立即生效**：本次起每次扫码把新型号写入 PLC `40007~40011`，
  相机按新型号对应的"点位→相机程序号"表切程序；设备连接不断开，无需重启。
- 型号下拉与系统设置 PLC 区"产品型号"是同一个值：主界面切换后设置里也同步显示；保存设置热更后
  主界面下拉候选自动刷新。

### 3.2 产品序列号（SN）
- 正常流程：扫码枪扫到条码自动填入（TCP 模式连上后自动发触发指令 `LON` 进入读码状态；
  串口模式上电即读码），标题栏"序列号:"实时更新。
- **手动输入（V1.12.19）**：无扫码枪、或扫码枪没读到码时，**鼠标点击标题栏"序列号"框**
  直接出现输入光标即可录入（无需弹窗）。交互：
  - **回车（Enter）**：提交生效（可随时补录，流程中也能改）；
  - **失焦**（点其它区域）：输入非空同样提交，空输入还原为上值（防误清空）；
  - **Esc**：放弃本次输入，还原为当前 SN。
  与扫码枪收码等效：存图目录同步按新 SN 归档，且在"等 SN"阶段输入会立即推进到拍照阶段。
- 序列号决定存图目录 `{年月日}/{SN}/OK|NG/`，换产品请确保 SN 正确。

### 3.3 放大查看某路画面（V1.12.15）
- **双击**任一显示窗口 → 该窗口全屏放大（覆盖整屏含任务栏），画面仍随检测实时刷新。
- **再次双击 / 按 Esc** → 还原回窗口矩阵原位置。
- 想换成另一路：全屏状态下直接双击另一窗口即切换。

### 3.4 查看来料图片
- 图片按模板自动归档到 `Config/appconfig.json` 的 `image.rootDir` 目录，默认结构：
  `根目录 / 年月日 / SN号 / OK|NG / 点位号.png`。
- 同 SN / 同判定 / 同点位二次拍照自动追加 `_2/_3…` 序号，不覆盖历史图。

<a name="part1-s4"></a>
## 四、登录账号（V1.9.0 / V1.12.0）

| 账号 | 默认密码 | 登录后进入 | 权限 |
| --- | --- | --- | --- |
| `admin` | `admin123` | 系统设置窗体 | 改配置、保存即热生效 |
| `dev` | `dev123` | 功能测试窗体 | 只做通讯手动验证，**不改配置** |

- 点"系统设置"按钮弹出登录框；密码错误会提示，**连续输错有次数限制**。
- 登录框内置**修改密码**面板（仅管理员可改）：验证原密码 → 新密码两次一致且 ≥6 位 → 保存。
- **记住密码**：勾选后用户名+密码用 Windows 账户加密保存在本机
  （`%LOCALAPPDATA%\CommandCenter\`，管理员 `remembered_login.dat`、开发者 `remembered_login_dev.dat`），
  下次自动回填；换 Windows 用户/换机失效。**V1.12.21：管理员与开发者记录互斥**——登录任一
  账号成功会清除另一账号的记住记录（如上次记住了 dev，这次用 admin 登录后 dev 不再自动回填），
  防止免密入口跨角色残留。
- 管理员密码只存 SHA-256 哈希，改哈希需通过登录框"修改密码"入口，不要手改配置。

<a name="part1-s5"></a>
## 五、系统设置（管理员）

登录 `admin` 后进入。所有修改点保存即热生效（免重启，设备短暂断连后自动连回）。

- **PLC**：监听绑定 IP（默认 `0.0.0.0`=所有网卡）、端口（默认 502）、从站 UnitId、
  **产品型号**（V2.7，最多 10 字符，每次扫码自动写入 PLC `40007~40011`；V2.8 起是**可编辑下拉**，
  候选项=**预置型号 `U171/U172/Z121` ∪ 已保存型号**（手输新型号保存自动加入候选。**切型号即切换
  该型号的相机程序映射**——保存后在"窗口/点位配置…"里按型号配好映射即可；主界面标题栏型号下拉
  与这里同一个值，操作员日常切型号在主界面直接选，无需进设置）；
  V2.7 握手寄存器地址（`40001~40011`，现场定稿后只改 `appconfig.json` 的 `plc` 节点）。
- **相机**：表格最左是只读**序号**列（=相机 ID，相机1=1、相机2=2…，删除某台后自动重排）；
  其余每台相机 IP、指令端口、取图方式（V1.12.18 起仅 FTP 推图，Tcp 已下线）、触发指令、超时等。
  相机台数=表格行数，增删即生效。⚠️ 若某台相机触发直接失败且日志报"设置判定输出格式失败"，
  多半是该相机"判定输出格式"列填了非法值（必须恰好 2 位数字，如 `00`）。
**点位→相机程序号（V1.12.25 按相机分表，V1.12.26 起下拉选择，V2.8 起按产品型号分表）**：现场"28 个
   窗口点位由两台相机分工拍摄"（上相机管一部分点位、下相机管另一部分），每台相机的程序库互相独立，
   且同台相机在不同产品型号下的程序号/点位归属也不同——点位→程序号按**相机各自配置**，且每台相机
   再**按产品型号分表**。入口在"窗口/点位配置…"，和最上面的窗口↔存图点位矩阵**同一个对话框**：
   下半区"相机程序映射"先选**相机**再选**型号**（"默认（不区分型号）"=旧映射表，其余=对应型号的表，
   型号候选=设置页产品型号下拉），然后**点位/相机程序号两列都用下拉选择**——**点位列=窗口点位
   （数量=窗口数）**，程序号列="不切换"+0~127（**程序按相机实际装的程序动态选，数量和编号与窗口数
   无关**；程序 0 也算一个程序、选中"不切换"=保持相机当前程序；某点位不归这台相机拍直接删掉该行）。
   触发时按"当前产品型号→点位"查对应型号表切程序，型号没配表就按默认表、仍没配就不切换。
   一台相机一行表 = 一台相机的独立映射；设置页相机表加一行新相机，新相机自然有自己的空表，也能
   立刻下拉配置，配好点确定写回、点保存生效（保存不会丢映射）。
  主界面相机下拉/状态灯**有名称（`name` 字段，如上相机/下相机）显示名称，无名称显示"相机N"**，
  N 即设置表里的序号。
- **扫码枪**：TCP 表（IP/端口/触发指令 LON）+ 串口表（串口名/波特率/停止位/校验位），
  启用勾选后才接入。
- **显示**：窗口行数×列数、标题栏字段开关、OK/NG 颜色名、**窗口右下角 OK/NG 徽标显隐开关**
  （`windowOkNgVisible`，V2.10.3，默认 false；勾选后每个显示窗口右下角叠加自绘矩形框 OK/NG，
  颜色随 OK/NG 颜色名，保存热更即时生效）、窗口→存图点位映射 + 点位→相机程序号
  （都在"窗口/点位配置…"对话框：上区改窗口对应的存图点位 / 交换位置 / 恢复默认，
  下区"相机程序映射"选**相机+型号**下拉配点位→程序号，V1.12.25 同页混排、V1.12.26 下拉选择、
  V2.8 按产品型号分表）。窗口可**禁用/启用**（右键格子或点"禁用/启用"，灰底显示"已禁用"；
  V2.10.1 起"交换位置"时禁用状态**随点位一起交换**——禁用的是点位而非格子）；某型号程序映射表
  被清空时保留原映射并弹提示（V2.10.1）。
- **图像**：保存根目录、"配置目录结构…"（逐级目录 + 文件名规则 + 实时预览）、FTP 监听目录。
- **安全**：管理员登录开关、账号、记住密码相关（账号维护在登录框完成，见 §四）。

> ⚠️ **FTP 取图（V1.12.22 定稿）**：FTP 推图由**基恩士工程师在相机软件（IV Navigator）里
> 配置**，相机作 FTP 客户端把照片推到**本机 `D:\IV存图\1`（相机1/上相机）与 `D:\IV存图\2`
> （相机2/下相机）**两个目录；上位机不装任何 FTP 服务器软件（FileZilla 等一概不用），程序按
> 相机配置 `ftpUploadDir` 监听这两个目录取图（`image.ftpRootDir` 仅作留空兜底）。
> 若现场 Ftp 模式图不到，先核对相机侧推图目标目录与 `cameras[i].ftpUploadDir` 是否一致。
> **双文件约定（V1.12.18；V1.12.24 起取图扫目录取最新文件）**：每次拍照相机生成 jpeg+iv4p 两个文件
> （**文件名不保证是 0000，可能是 0084 等任意编号**），程序按扩展名配对、两个都到齐才算图到位，
> 归档时**自动扫该相机 FTP 目录取修改时间最新的一对**（事件漏报也能兜底取到），**归档到正式存图
> 目录后会自动删除 FTP 源文件**（FTP 目录只当中转暂存区，处理即删，同一目录里新旧图不会混淆）。

## 六、功能测试（开发者）

登录 `dev` 后进入 `DevTestForm`，用于 PLC 业务逻辑未写完时单独验证通讯链路：

- **相机**：T1 仅触发 / **T2 触发+读判定+取图存图**（V1.12.24：点 T2 拍照后自动从该相机 FTP 取图
  目录拿**最新** jpeg 闪图，并按主窗体设置的存图目录归档一份，**点位固定 1**，路径显示在右侧与日志里；
  **归档成功后自动删除该相机 FTP 取图目录里的源图**（V1.12.25，与主流程"处理即删"一致，测试多次
  拍照不会把相机目录越堆越多）；
  **触发后会自动等最多 5 秒的 FTP 推图**（V1.12.27，不再立即扫目录，避免取到旧图/空目录）；
  若提示"取图失败"或"存图成功但预览加载失败"，先看该相机 FTP 目录里有没有新图、推图目标目录是否
  配置一致、图是否被占用打不开）。
  - **切程序（V1.12.20，基恩士侧调试中）**：`读当前程序号`（PR）→ 显示当前 `Pxxx`；
    `切换程序→P001` / `切换程序→P002`（PW,001 / PW,002）→ 切换成功会自动读回确认。
    现场有多个点位程序（P000/P001/P002…）时，先切程序再点 T2 验证连拍。
- **PLC**：读地址 / 写地址测试（含协议偏移量配置），读扫码请求（40001）/ 读相机请求（40002+40003）、
  写产品型号（40007~40011）、写扫码结果（40004：0 复位 / 1 OK / 2 NG）、写上/下相机结果
  （40005/40006：1 OK / 0 复位）——对应 V2.7"请求-结果-复位"三拍握手，手动模拟各拍验证。
- **扫码枪**：实时展示收到的条码，可手动重发触发指令 `LON`。

⚠️ 复用主窗体已建连接、不新建连接；**业务流程运行时不要在测试页操作 PLC 握手寄存器区**
（40001~40011），会干扰生产流程。

## 七、常见问题排查（现场速查）

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| PLC 灯红 | 502 端口被占用 / 绑定 IP 不对 / 防火墙未放行 | 悬停灯看提示；查端口、防火墙入站 502 |
| PLC 灯黄 | 从站就绪但主站未连入 | 检查 PLC 主站程序是否运行、是否指向本机 IP:502 |
| 扫码枪一直断连 | 调试助手等工具占着连接（扫码枪单客户端） | 关闭调试助手连接再重启本程序 |
| Ftp 模式图不到 | 相机侧 FTP 推图未配置好 / 推图目标目录与程序监听目录（相机 `ftpUploadDir`，默认 `D:\IV存图\1/2`）不一致 / 相机还没推图（取的是目录里最新的一张，命名是 0000 或 0084 等任意编号都行） | 联系基恩士工程师核对相机推图目标目录（应分别指向本机 `D:\IV存图\1` 与 `D:\IV存图\2`）；上位机无需部署任何 FTP 服务器；确认目录里确实有刚拍的 jpeg |
| 界面点按钮半天没反应 | 把网络操作放 UI 线程（正常不应发生） | 重启程序；日志报给维护方 |
| 放大窗口没反应 | 双击落在非图片区域 | 双击应落在图像区（整个窗口）即可 |

<a name="part1-s8"></a>
## 八、换场地 / 换设备怎么改

所有通讯参数都在 `Config/appconfig.json`（或设置窗体可视化修改），**现场改配置即可，不改程序**：

- 换相机/扫码枪 IP：改 `cameras[].ipAddress` / `scanners[].ipAddress`。
- 相机程序号（V1.12.25 起按相机分表，V1.12.26 起下拉选择，**V2.8 起按产品型号分表**）：在
  "窗口/点位配置…"对话框下半区"相机程序映射"里，选**相机**和**型号**（"默认"=旧映射表，其余=对应
  型号）后从下拉选该相机该型号下的"点位→程序号"（**点位=窗口点位，数量=窗口数**；程序号="不切换"
  或 0~127，**按相机实际装的程序动态选，数量/编号与窗口数无关**；某点位不归这台相机拍直接删行）；
  或直接改 `cameras[].modelStationPrograms`（`[{"modelName":"U171","programs":[{"stationNo":1,"programNo":0},…]},…]`，
  型号没配就用 `cameras[].stationPrograms` 默认表）。触发前程序按"当前型号→本轮点位"查表自动发
  `PW,nnn` 切换，没配的点位不切。**预置映射**：上相机 U171=P000~P012/U172=P013~P028、
  下相机 U171=P000~P003/Z121=P005~P007。**新增相机（设置表加一行）
  自动有自己的空表**，配好后点保存映射不会丢。
- 换 PLC 地址：改 `plc.ipAddress`（上位机固定 IP 需先配到网卡再填同值）。
- 换扫码枪触发指令：改 `scanners[].triggerCommand`（如非 `LON`）。
- 调整窗口矩阵：改 `display.rows/columns`。

# 第三部分 扫码枪对接（基恩士 SR）

> 客户确认扫码枪也是基恩士的。SR 系列支持串口 RS-232 与以太网 TCP/IP 无协议两种
> 通讯（无协议方式与 IV4 相机同思路：上位机作 TCP 客户端）。本程序两种都支持，
> 在 `appconfig.json` 的 `scanners` 列表里用 `mode` 二选一（V1.8.1 起为列表）。

## 3.1 配置（appconfig.json → scanners，V1.8.1 起为列表，支持多台）

```json
"scanners": [
  {
    "enabled": true,
    "mode": "Tcp",           // "Tcp"=基恩士以太网无协议（上位机作客户端收条码行）；"Serial"=串口
    "ipAddress": "19.87.6.100",  // 现场实测默认，可按现场改
    "port": 9004,            // 基恩士 SR 无协议监听端口，现场实测默认
    "triggerCommand": "LON", // V1.12.1 触发指令：Tcp 连上后自动发送并补 \r\n，扫码枪才读码；留空不发
    "portName": "COM3",      // 仅 Serial 模式
    "baudRate": 115200,
    "stopBits": "1",
    "parity": "None"
  }
]
```

> 多台：列表加一行即可（不同工位/不同门各一把）；任何一台扫到的条码都会更新当前
> 序列号（标题栏 + 存图 {SN} 目录同步）。设置窗体"扫码枪列表"可视化增删改（V1.12.8 起
> TCP 与串口拆为两张表：TCP 表配 IP/端口/触发指令，串口表配串口名/波特率/停止位/校验位，
> 方式由所在表决定，不再有"方式"下拉列），`enabled` 不打勾则该台不接入。
> **V1.12.9 起 TCP 表默认行与"添加一台"默认勾选"启用"**——与代码默认接入的以太网扫码枪
> （`19.87.6.100:9004 / LON`）一致，打开设置即体现；串口表默认行不勾选（代码默认不用串口枪）。

## 3.2 Tcp 模式（ScannerTcpService，V1.12.1）

- 上位机作 **TCP 客户端**连扫码枪（`ipAddress:port`），**连接成功后自动发送触发指令**
  `triggerCommand`（默认 `LON`，帧尾补 `\r\n`）——基恩士 SR 无协议模式**不是连上就回数据**，
  多数机型需先发"打开激光/开始读取"指令才进入读码状态（现场实测）；
  断线自动重连后也会再次发送，扫码枪始终处于可读状态；
- 之后扫码枪读到条码后把条码文本（通常 + CR/LF）**主动推送**给连接方，与串口行为一致，
  按行切分，一行=一条码；
- 后台线程：连接 `BeginConnect+WaitOne` 强制超时（2s）→ 发送触发指令 → 阻塞读流按行收码；
  断线按 3s 节流**静默自动重连**，连上即恢复，不打扰主流程；
- **KeepAlive 探活（V2.10.4）**：连接启用 TCP KeepAlive（空闲 5s 开始探测、间隔 5s）。这是为了
  **检测"拔网线 / 扫码枪断电 / 交换机断电"这类静默断连**——这类断连没有 FIN/RST，阻塞读流永远
  等不到数据，若不探活，状态灯会一直停在"已连接"绿、也不重连（要等系统默认 2 小时才暴露）。
  启用后判死约在数十秒内，随后自动走重连并重发 `LON`，状态灯同步转红再回绿；
- ⚠️ **扫码枪只接受一个 TCP 客户端（V1.12.5 现场实测确认）**：用网络调试助手/其他工具占着连接时，
  上位机连上即被踢或拒绝，表现为"一直断连"。调试助手测完必须**关闭连接**再重启本程序。
  看日志区分两种情况：
  - `扫码枪(TCP)连接失败（后台持续重连）` → 一直没连上，多半端口占用/地址不对；
  - `扫码枪(TCP)连接断开，3s 节流后自动重连` → 已连上又被踢，检查是否被调试助手等占用。
- 功能测试窗体（DevTestForm）提供"发送触发指令"按钮可手动重发 LON；
  扫码枪状态灯随真实连接实时变色（绿=已连接/红=断连，V1.12.5 起订阅 `IScanner.ConnectionChanged`）；
- 扫到的条码 → `ProductionCoordinator.LatestSerialNumber`（进标题栏"序列号:"与存图 {SN} 目录）。

## 3.3 Serial 模式（ScannerService）

- 监听 `portName` 串口 DataReceived，按 CR/LF 切行，一行=一条码；串口打不开不影响主流程。

## 3.4 扫码枪现场校准清单

- [ ] **确认扫码枪无协议模式的监听端口与触发指令**：默认 `19.87.6.100:9004 / LON` 为现场实测值，
      换场地换扫码枪仍要实测确认（触发指令可能是其它值，改 `scanners[].triggerCommand` 即可，不用改代码）
- [ ] 扫码枪设成 TCP 服务器（无协议）模式，确认监听端口与 `scanners[].port` 一致
- [ ] 程序日志出现 `扫码枪(TCP)已连接` + `扫码枪(TCP)触发指令已发送：LON`，扫码枪激光应打开开始读码
- [ ] 用网络调试工具连扫码枪扫一下，确认收到"条码 + CR/LF"文本行（若有头/尾附加字符，
      按实测在 `ScannerTcpService.ReadLoop` 的切行逻辑里处理）
- [ ] 程序日志出现 `扫码枪收到条码：xxx` 且标题栏"序列号:"随之更新
- [ ] 断线（拔网线/重启扫码枪）后 3~5s 内自动重连，日志出现 `扫码枪(TCP)已连接`，重连后触发指令自动重发
- [ ] ⚠️ **调试助手占用排查（V1.12.5）**：扫码枪只接受一个 TCP 客户端，用调试助手测试时

      "连接断开"两种形态，见 3.2 说明）
- [ ] ⚠️ **扫码枪配置务必在"系统设置→扫码枪列表"里填**（V1.8.1 起配置是 `scanners` 数组），
      手改 json 里旧版单对象 `scan` 段不会生效（会被忽略，扫码枪不会启动）

<a name="part4"></a>
# 第四部分 相机对接（基恩士 IV4-500CA）

## 4.1 硬件能力

IV4 系列内置以太网，支持：EtherNet/IP、PROFINET CC-B、**TCP/IP 无协议通信**（最多 2 路连接）、FTP/SFTP 客户端、SNTP、OPC UA 服务器、MQTT 客户端。(来源：基恩士官网 IV4-500CA 规格页)

## 4.2 对接方式（V1.0.1，V1.7.0 增加 TCP 直读取图，V1.12.18 起仅保留 Ftp 取图 + PW 切程序）

上位机作为 TCP 客户端，连接相机 `CommandPort`（默认 8500，可改）。指令均为 ASCII 文本，
正文以 **CR（`\r`，0x0D）** 结束（相机回帧则以 CR 或 CRLF 结束，程序两者兼容）。

1. **触发拍摄（T1）**：发送 `CameraConfig.TriggerCommand`（默认 `T1`）。相机仅执行拍摄，
   不返回判定，适合"只拍不断判、判定交给别的设备"的场景。
   **CR 语义**：发送 `T1[CR]`（程序自动补 `\r`），相机收到后回显 `T1[CR]` 作为确认帧——
   CR（回车符 `\r`）是数据包结束标记，双方靠它识别帧边界。程序只需确认收到回显
   （`SendTrigger` 返回 `raw != null`）即视为触发成功，不解析回显内容。
2. **触发拍摄 + 读取判定（T2，本程序默认走这条）**：发送 `CameraConfig.TriggerAndReadCommand`
   （默认 `T2`）。相机拍摄后**直接返回最新一次判定结果**，一次通讯完成"触发 + 拿结论"，
   与现场"拍照即得 OK/NG"要求一致。响应例：`RT,00000000`（读实型/判定结果，见下）。
3. **单独读取判定（RT）**：在已有拍摄结果的前提下，发送 `CameraConfig.ReadResultCommand`
   （默认 `RT`）只读最近一次判定，支持"先 T1 触发、稍后再取结论"的异步节拍。
4. **判定响应格式**：`RT,xxxxxxxx` —— 逗号后为"标准结果"8 位字符，**每位对应一个工具**
   （工具顺序由 IV4 流程配置决定）：`0`=OK、`1`=NG、`4`=未进行、`-`=工具未启用。
   本程序判定规则（`KeyenceIV4Camera.ParseResult`）：
   - 全部判定位为 `0`（合格位）→ OK；
   - 存在 `1` 或任何非合格位（`4`/`-`/未知字符）→ 保守判 NG；
   - 结果为空、响应缺 RT 前缀、超时/断连 → 本次通讯失败，走 Done=2。
5. **切换相机程序（PW，V1.12.18 新增；V1.12.25 起按"点位→程序号"映射表驱动）**：指令
   `PW,nnn[CR]`（nnn=程序号 000~127，**3 位补零**）。
   相机响应 `PW[CR]` 表示成功；`ER,PW,03[CR]`（程序号无效）/ `ER,PW,22[CR]`（无法切换）为失败。
   **用途**：现场"28 个窗口点位由两台相机分工拍摄"，一个点位对应本相机里一个程序，触发前必须先
   切到该点位程序。程序号不再读固定 `CameraConfig.ProgramNo`（该字段 V1.12.25 起废弃），而是
   **按相机+型号查映射表**（V1.12.25 每相机一张默认表 `StationPrograms`；**V2.8 起再按产品型号
   分表 `ModelStationPrograms`**：先查与当前型号同名的那张表、型号没配表才回退默认表；
   表里配了哪些点位就是这台相机负责拍哪些点位）——`TriggerOneCamera` 触发前先按"本轮该相机要填的
   窗口"（`_nextWindowIndex + idx`，与 FinishAll 环形窗口分配一致）经 `ResolveStation` 得点位号，
   再 `ResolveProgramForStation` 查本相机表：**命中先 `PW` 切到该点位程序再 T2；未命中不切换**
   （该点位不归本相机拍或还没配映射，保持相机当前程序）。切失败则该次触发中止、直接记取像失败
   （防止用错程序拍出无意义图）。
   **配套**：`KeyenceIV4Camera.ReadProgramNo()`（`PR[CR]` → `PR,nnn[CR]`）可在功能测试页读回
   当前程序号核对。切程序是点位差异化拍摄的基础（程序号由本轮窗口点位驱动，见 5.3）。
6. **设置判定输出格式（OF，V1.12.18 新增）**：指令 `OF,nn[CR]`，nn=00 标准 / 01 详细 /
   02 标准主控 / 03 详细主控（详细=带每个工具结果）。相机响应 `OF[CR]`。由
   `CameraConfig.OutputFormat` 配置（默认 `00`），`KeyenceIV4Camera.SetOutputFormat(string)`
   在 T2 触发前调用。判定解析只认"标准结果"8 位串，详细格式主要用于现场用网络调试助手
   人工核对工具位，程序不解析详细正文。
7. **读取最新图像（BR，V1.7.0 新增，Tcp 取图模式）**：指令 `BR,m[CR]`（m=压缩率，见
   `CameraConfig.ReadImageMode`；`0`=无压缩，`1`=1/2 压缩）。响应：
   ```
   BR,nnnnnnnnnn,ddddddd,<图像数据>
   ```
   - `nnnnnnnnnn`：**合计触发编号**（10 位十进制；通过计数模式时固定为 999999999，
     一般模式为 0~DWORD_MAX-1）；
   - `ddddddd`：**图像数据的数据长度**（真正决定后面要读多少字节的字段）；
   - 逗号后紧跟**二进制**图像数据（24bit 位图，期望为完整 BMP 文件，即 `BM` 文件头 + 像素）。
   > **V1.9.1 修正**：此前版本把"合计触发编号"误当成图像字节数、把"数据长度"当成属性，
   > 正好颠倒导致按触发编号读图失败。现按手册顺序"触发编号 → 数据长度"重新解析，
   > 触发编号仅透出日志对照。
   解析要点（`KeyenceIV4Camera.ReadImage`）：图像数据是二进制、可能含任意字节（含 0x0D/0x0A），
   必须先用状态机精确读完 ASCII 头部，再按长度字段精确读 N 字节，不能按"读一行"处理。
   > **无最新图像时报错**：手册说明"在没有最新图像的状态下试图读取"会出错，此时响应不是
   > 正常 `BR,...` 帧（可能断连/回错误码），前缀校验不过即判失败并走断连重连。
   > **Tcp/BR 已下线（V1.12.18）**：代码保留仅作旧配置兼容，现场只走 FTP 取图。
8. **图像回传（FTP 推图，V1.12.18 起唯一取图方式）**：每台相机在 `CameraConfig.ImageSource`
   里独立选择，**现场只保留 `Ftp`**（V1.12.18 起设置窗体不再提供 Tcp 选项）：
   - **Ftp（默认，成熟）**：基恩士工程师在相机软件（IV Navigator）里把相机配成 FTP 客户端
     并推图；**上位机零配置、无需部署任何 FTP 服务器**（FileZilla 等一概不用），程序只监听
     相机推图落盘目录。
     **多相机（V1.1.0）**：每台相机的 FTP 上传目录独立配置（`CameraConfig.FtpUploadDir`，
     为空则回退全局 `ImageConfig.FtpRootDir`）——多台务必分开，否则新图归属无法区分。
     上位机为每台相机各建一个 `FileSystemWatcher`，新图事件带相机索引。
     **双文件约定（V1.12.18；V1.12.24 起取图改"扫目录取最新"）**：基恩士每次拍照必然生成两个文件——
     jpeg（显示/归档主体）+ iv4p（基恩士私有复盘格式，上位机不解析、**原样复制归档**）。
     **文件名不保证恒为 `0000`**（现场实测可能推 `0084.jpeg`/`0084.iv4p` 等任意编号），程序**不写死
     文件名**：`OnFtpFileArrived` 按扩展名配对（`FtpJpegPath`/`FtpIvpPath`）作信号加速（两个都到齐
     才算 `IsSnapped` 提前收尾），归档时 `FinishAll` 经 `TryResolveFtpSources` **重扫相机 FTP 目录取
     修改时间最新的一对**（`ImageStore.FindLatestPair`），扫描失败才回退事件路径；归档成功后删除
     **实际归档的那对** FTP 源文件（中转暂存区逻辑，处理即删，防同点位重复触发时新旧图混淆）。
9. 断线处理：TCP 连接 `BeginConnect+WaitOne` 强制超时，失败自动重连；
   **KeepAlive 探活（V2.10.5）**：连接启用 TCP KeepAlive（空闲 5s 探测、间隔 5s）——
   **拔网线/相机断电这类静默断连（无 FIN/RST）** 之前靠 2s 心跳 `Poll` 测不出（相机空闲
   不拍照时 UI 灯一直绿、到下次触发遇读写异常才暴露）；启用后 TCP 栈判死约数十秒，
   心跳/下次动作都能立即感知并走自动重连，UI 灯同步转红再回绿。
   图片等待有 `ImageWaitMs`（默认 10s）兜底超时（FTP 取图为主，Tcp 模式为同步取图基本不靠它）。
   指令正文与换行符均可在 `appconfig.json` 的 `cameras` 数组节点分别修改。

## 4.3 实现细节与易踩坑点（排障必读，与代码逐条核对过）

> 本节是"文档与代码一致"的校验结果。改相机代码/配置时先对照这里，别把语义改漂了。
> 涉及方法：`ProductionCoordinator.TriggerOneCamera`（触发编排）、`KeyenceIV4Camera.SwitchProgram/
> SetOutputFormat`（指令）、`ImageStore.SaveImageFilePair`（归档）、`OnFtpFileArrived`（配对）。

**① 触发前的指令顺序（固定）**：`OF`（设输出格式）→ `PW`（切程序）→ `T2`（触发+读判定）。
三步任一失败立即中止该相机（`FailReason`），**宁可不拍也不拍错**（程序没切对，判定/取图都对应错点位）。

**② `ProgramNo` 判据是 `>= 0`，不是 `> 0`**：0 也是合法程序号（相机程序从 0 开始编号），
`ProgramNo=0` 必须发 `PW,000`。只有 **-1（默认值）才表示"不切换"**。设置窗体该列填 `-1` 或不填都行。
**V1.12.25 起改由映射表驱动（V2.8 起按型号分表）**：`ResolveProgramForStation` 先查本相机
`ModelStationPrograms` 里与当前产品型号同名的表（大小写不敏感）、型号没配表再查 `StationPrograms`
默认表，`StationProgramItem.ProgramNo >= 0` 才视为命中（0 合法、会发 `PW,000`）；点位在表里但程序号是
-1（设置页留空/非法）同样不切换——**映射表"命中"跟"程序号 >= 0"是两条独立判断**，别混淆。

**③ `OutputFormat` 必须恰好 2 位数字**（`00`~`03`）：`SetOutputFormat` 里校验长度=2 且两位都是数字，
配置非法（如 `"0"`、`"A0"`、`"000"`）→ 直接返回 false → **该相机触发直接失败**（FailReason="设置判定输出格式失败"）。
默认 `""`（空）不发送 OF，相机维持当前格式。

**④ `SwitchProgram` 程序号越界自动夹取**：配置 128+ 不报错，而是 `Math.Max(0, Min(127, n))` 夹到
0~127（如配 200 → 实际切到 127）。想验证配置是否真的切对程序，用 `ReadProgramNo()`（PR 指令）读回核对。

**⑤ FTP 双文件到达顺序不保证**：`FileSystemWatcher` 对 jpeg/iv4p 各触发一次 Created/Renamed，
谁先到不一定。`OnFtpFileArrived` 按扩展名分派槽位，**两个都填满才算 `IsSnapped`**（事件只作"图到→
提前收尾"的信号加速）；只来一个文件时继续等，最终由 `ImageWaitMs`（默认 10s）超时兜底。
**V1.12.24 放错机制**：即使事件漏报/文件名非 0000（如 0084），收尾归档时 `FinishAll` 也会**重扫相机
FTP 目录取修改时间最新的一对**（`ImageStore.FindLatestPair`），目录里有图照样归档——超时兜底不再
"有图不存"。

**⑥ 归档与删除顺序硬约束**：`FinishAll` 里**先** `SaveImageFilePair` 复制归档、**成功后才**
`DeleteFtpSource` 删 FTP 源文件。删除的是**实际归档的那对**（`TryResolveFtpSources` 扫目录取到的
最新对，事件路径仅兜底）。若归档失败（返回 null），**不删源文件**，回退用 FTP 源 jpeg 路径当
显示结果（图至少能看）；删除失败只记 Warn 日志不阻断（文件不存在=已删，正常）。
删除必须在归档成功之后——否则复制失败时源文件没了，图就真丢了。

**⑦ `SaveImageFilePair` 只复制不删除**：方法本身不碰 FTP 源文件，删除职责在协调器 `FinishAll`，
两者解耦，避免单点删错。

**⑧ iv4p 文件"原样复制"**：上位机不解析 iv4p 内容（基恩士私有复盘格式），`File.Copy` 原样搬运。
归档文件名 = 模板渲染 + `FileTimestampSuffix` 时间戳（默认 true），jpeg/iv4p **同名不同扩展名**，
成对落在同一目录。

**⑨ 归档失败时 Tcp/BR 分支提示**：`archived==null` 且 `ImageBytes==null`（Tcp 模式）时明确报错
"图像归档失败（TCP 取图，内存解码失败）"；FTP 模式则回退用源文件，行为不同、别混。

**⑩ 判定成功≠图到手**：`TriggerOk`（触发/判定成功）与 `IsSnapped`（图到齐）是两个独立标志。
触发成功但图没到 → 超时记失败（`Done=2`）；图到但判定为 NG → 图照样归档（`Done=1`，含NG）。

# 第五部分 PLC 通讯对接（汇川）与对外协议定义

<a name="part5-s1"></a>
## 5.1 通讯角色与硬件配置

- **V1.12.11 起角色反转**：上位机做 Modbus TCP **从站**监听本机 502，现场汇川 PLC 做**主站**
  TCP 连入读写上位机保持寄存器区。PLC 侧连入地址 = 上位机 IP:502，站号 UnitId=1（上位机配置）。
- **地址映射（V1.12.14 现场实测确认）**：上位机从站协议地址与 PLC 侧 D 地址**一一对应、零偏移**——
  上位机写 D101，PLC 主站直接读地址 101 即见（不需要 +40001 绝对地址换算，也没有 0/1-based 错位）。
  原因：NModbus 从站 `PointSource.ReadPoints/WritePoints(start,…)` 的 start 是 0-based 协议地址，
  PLC 主站通讯指令里填的 D 地址同为 0-based，两者天然对齐。
- 上位机从站监听绑定 IP 默认 `0.0.0.0`（所有网卡）；若上位机固定 IP（如 19.87.6.230），
  需先给网卡配上该 IP，再在设置窗体 PLC IP 填同值（或保持 0.0.0.0），否则绑定失败。
- 防火墙需放行 502 端口入站。
- **主站静默断连检测（V2.10.5）**：从站对已连入的每个主站会话启用 TCP KeepAlive（空闲 5s
  探测、间隔 5s）。此前 NModbus 从站不设 keepalive，汇川主站拔网线/断电（无 FIN/RST）时
  死会话不会自动清理，界面"主站已连入"三态灯会一直停在绿；启用后 TCP 栈判死约数十秒，
  NModbus 自动踢掉死会话，三态灯转红，主站恢复连入后再转绿。

| 40005 | 上相机拍照结果 | PLC只读 | 0/1/2/3 | 0=默认/复位，1=OK，2=NG（失败/超时），3=点位禁用跳过 |
| 40006 | 下相机拍照结果 | PLC只读 | 0/1/2/3 | 同上相机结果 |
| 40007~40011 | 产品型号（10字符） | PLC只读 | ASCII | 每寄存器 2 字符（高字节=前字符、低字节=后字符），不足补 `0x00`，超 10 字符从 40012 向后扩展 |

> **SN（产品序列号）不进寄存器**：SN 由上位机扫码枪直接接收，仅用于标题栏显示与存图 `{SN}` 目录，
> PLC 不读取；**产品型号**才是上位机固定下发、PLC 读走的参数（`productModel`，设置窗体"产品型号"
> 输入框改，每次扫码完成自动写 40007~40011）。

> 配置：地址全部收进 `Config/appconfig.json` 的 `plc` 节点
> （`scanRequestAddress`/`camUpRequestAddress`/`camDownRequestAddress`/`scanResultAddress`/
> `camUpResultAddress`/`camDownResultAddress`/`productModelAddress`/`productModelLen`），
> 现场只改 json 不动程序。功能测试页（DevTestForm）可手动"读请求/写型号/写结果"验证。

## 5.3 完整业务流程（三拍握手，V2.7 定稿）

> 整条产线节奏：**扫码得 SN → 相机拍照 → 上报结果 → 走下一工位**。上位机做从站，所有请求由
> PLC 主站写入上位机寄存器区（上位机轮询读），处理结果由上位机写自己区（PLC 主站轮询拉取），
> 每拍走"**PLC 写请求≠0 → 上位机写结果≠0 → PLC 复位请求=0 → 上位机复位结果=0**"。

```
     PLC(主站)                          上位机(从站)
  ──────────────                    ─────────────────
  ① 写 40001=1（扫码请求）───────> ② 轮询到扫码请求 → 触发扫码枪读码
                                      （TCP LON / 串口）→ 收到产品 SN（标题栏+存图{SN}目录）
                                      → 写 40007~40011=产品型号 + 写 40004=1（OK）/2（超时NG）
  ←── ③ 读到 40004≠0 + 型号，写 40001=0（复位请求）
  ───────────────────────────────── ④ 轮询到 40001=0 → 写 40004=0（复位结果）→ 回到等待
  ⑤ 写 40002=点位（上相机拍照请求）→ ⑥ 轮询到 40002≠0 → 解析点位→窗口
                                      → 触发拍照（先 PW 切点位程序 → T2 触发+读判定 OK/NG）
                                      → 取图（FTP jpeg+iv4p，扫目录取最新对）→ 双文件归档+删源图 → 显示窗口
                                      → 写 40005=1（OK）/2（NG）
  ←── ⑦ 读到 40005≠0，写 40002=0（复位请求）
  ───────────────────────────────── ⑧ 轮询到 40002=0 → 写 40005=0（复位结果）→ 回到等待
  下相机同理：40003 请求 / 40006 结果，重复 ⑤~⑧；点位禁用/无相机时上位机直接写结果 3（跳过）
```

> **节点说明**
> - ② 扫码：VIP 扫码枪为设备主动推码的模式（串口上电即读码 / TCP 连上自动发 `LON` 触发），
>   上位机**订阅 `SerialNumberScanned` 事件收码**，SN 落 `ProductionCoordinator.LatestSerialNumber`；
>   若现场是"指令式"取码（上位机发指令才回），则复用扫码枪的 `SendTrigger()` 手动触发。
> - ⑤ 拍照：`T2` 一次完成"触发 + 读判定"；触发前先查**本相机"点位→程序号"映射表**
>   （`stationPrograms` 默认表 + **V2.8 按型号分表 `modelStationPrograms`**，先查当前型号同名表、
>   型号没配表回退默认表）→ 命中先 `PW` 切到该点位程序再触发、未命中不切换，
>   切失败即中止（V1.12.18）；未配判定时退化为"FTP 图到即记 OK"。
> - ⑦ 每张图一个 `WindowData` 提交、按窗口点位映射环形刷新显示窗口；jpeg+iv4p 双文件归档
>   （V1.12.18 原样复制，jpeg 为显示主体），归档前**重扫取图目录取修改时间最新的一对**
>   （V1.12.24 放错机制，不写死 0000，事件漏报也能兜底取到），成功后删除实际归档的那对 FTP 源文件。

## 5.4 代码实现情况（V2.7 三拍握手，`ProductionCoordinator` 状态机）

> V2.7 起 `ProductionCoordinator` 按"请求-结果-复位"三拍握手驱动**三通道状态机**
> （通道①扫码、通道②上相机、通道③下相机）：后台轮询读请求寄存器 → 处理完写结果 → 等 PLC
> 复位请求 → 再复位结果，回到等待。实现要点：
>
> 1. **通道①扫码（40001/40004）**：轮询到 40001≠0 → 对每台扫码枪 `SendTrigger()` 触发读码进入
>    "等 SN"；**无扫码枪**（列表为空）SN 走手动输入。扫到/超时后写 40007~40011=产品型号
>    （`_productModel`，当前型号：设置窗体保存或**主界面标题栏型号下拉**切换，V2.8）
>    + 40004=1（OK）/2（超时 NG）→ 等 PLC 把 40001 复位为 0 →
>    写 40004=0 复位结果、回到等待。
> 2. **通道②③相机（40002/40005、40003/40006）**：轮询到请求≠0 → 读点位编号 → 解析点位→窗口，
>    判断"点位禁用/该通道无相机"则直接写结果 **3（跳过）** 告诉 PLC 走下一工位；正常则触发拍照
>    （先 PW 切点位程序 → T2 读判定 OK/NG → 取图归档）→ 写结果 **1（OK）/2（NG）** → 等 PLC
>    复位请求 → 复位结果。
> 3. **等 SN 超时兜底（`ScanWaitMs`，30s）**：产品没贴码/扫码枪没读到 → 上报扫码 NG(2) 不卡流程；
> 4. 实现沿用现有后台轮询 + 事件驱动范式，原相机拍照闭环逻辑保留未动。
>
> **点位→程序号联动（V1.12.18 起按窗口点位暂定；V1.12.25 已按相机映射表落地；V2.8 起按型号分表）**：
> 触发前按"本轮该相机要填的窗口"（`_nextWindowIndex + idx`）经映射表 `WindowStationMap` 解析出点位号
> （详见 4.4），再查**本相机的映射表**（先查 `ModelStationPrograms` 里当前型号同名表、型号没配表
> 回退 `StationPrograms` 默认表，设置页 WindowPointForm 相机+型号下拉同页编辑）执行 `PW` 切程序：
> 命中→切、未命中→不切换。V2.7 起点位来源即 PLC 请求 40002/40003 里带的点位编号（触发前再按窗口
> 映射核对归属相机）。

**地址映射总表**

| 1    | **40001** | 扫码请求             | **PLC只写**     | `0` 或 `1`    | `0`=无请求，`1`=请求扫码                |
| 2    | **40002** | 请求拍照上相机       | **PLC只写**     | `0` ~ `255`   | `0`=无请求，`1~255`=对应点位编号        |

**地址分类速查**

PLC → 上位机（PLC只写，上位机读取）：

| PLC地址 | 寄存器名称     | 取值说明                     |
| :------ | :------------- | :--------------------------- |
| 40001   | 扫码请求       | `0`=无请求，`1`=请求扫码     |
| 40002   | 请求拍照上相机 | `0`=无请求，`1~255`=点位编号 |
| 40003   | 请求拍照下相机 | `0`=无请求，`1~255`=点位编号 |

上位机 → PLC（PLC只读，上位机写入）：

| PLC地址     | 寄存器名称         | 取值说明                                  |
| :---------- | :----------------- | :---------------------------------------- |
| 40004       | 扫码结果           | `0`=默认，`1`=OK，`2`=NG                  |
| 40005       | 上相机拍照结果     | `0`=默认，`1`=OK，`2`=NG                  |
| 40006       | 下相机拍照结果     | `0`=默认，`1`=OK，`2`=NG                  |
| 40007~40011 | 产品型号（10字符） | ASCII编码，每寄存器存2字符，不足补 `0x00` |

**地址布局示意图**

```text
地址范围         内容                              方向（PLC视角）
─────────────────────────────────────────────────────────────────
40001 ~ 40003    请求区（扫码/上相机/下相机）       PLC只写
40004 ~ 40006    结果区（扫码/上相机/下相机）       PLC只读
40007 ~ 40011    型号区（10字符，5个寄存器）        PLC只读
40012 ~ ...      预留                              可向后扩展
```

> **扩展说明**：若后续型号长度超过10个字符，可直接从 `40012` 开始向后增加寄存器，不影响 `40001` ~ `40006` 的请求和结果地址，双方无需修改已有逻辑。

**产品型号（字符串）编码说明**

- 共5个寄存器（`40007` ~ `40011`），最多可传递 **10个ASCII字符**。
- 每个寄存器存放两个字符：**高字节（Bit 8~15）= 前一字符，低字节（Bit 0~7）= 后一字符**。
- **示例**：型号为 `"Z1212"`，则：
  - `40007 = 0x5A31`（'Z'=0x5A，'1'=0x31）
  - `40008 = 0x3231`（'2'=0x32，'1'=0x31）
  - `40009 = 0x3200`（'2'=0x32，`\0`=0x00 结束）
  - `40010 ~ 40011 = 0x0000`
- 不足10个字符的，在最后一个有效字符后面填 `0x00` 表示字符串结束。
- 若后续发现型号超过10个字符，从 `40012` 开始向后扩展即可。
- **型号来源（V2.8）**：上位机设置窗体"产品型号"下拉选择（候选=顶部 `productModels`，现场预置
  `U171`/`U172`/`Z121`，可手输新型号自动加入），保存后每次扫码把当前型号写入本型号区。**型号同时
  决定相机程序映射**（`modelStationPrograms`，见本文档 4.4/4.5）：切型号即切换对应的"点位→相机程序号"表，
  触发相机时按新型号发 `PW,nnn` 切程序。

| :------------------------ | :--------------- | :----------------------------------------------------------- |
| PLC读取 `40004` ~ `40011` | 03（0x03）       | 读保持寄存器                                                 |

### 5.5.5 异常处理约定

| 异常情况                      | 处理方式                                                     |
| :---------------------------- | :----------------------------------------------------------- |
| 扫码超时（如5秒未返回SN）     | 上位机写 `40004 = 2`（NG），界面报警"扫码超时"，流程继续     |
| 上相机拍照超时（如5秒未完成） | 上位机写 `40005 = 2`（NG），界面报警"上相机拍照超时"，流程继续 |
| 下相机拍照超时（如5秒未完成） | 上位机写 `40006 = 2`（NG），界面报警"下相机拍照超时"，流程继续 |
| 通信中断                      | 上位机界面显示"通信中断"，PLC侧建议做超时保护（如3秒未收到反馈则报警） |

### 5.5.6 PLC侧配置要求

1. 请将上述 `40001` ~ `40011` 共11个寄存器，按**连续地址**映射到PLC内部可读写的地址区域。
2. 请确保PLC的Modbus TCP主站功能已开启，目标从站IP = `19.87.6.230`，端口 = `502`，Unit ID = `1`。
3. **地址无偏移**：实测确认，PLC写入地址与上位机读取地址一致，无需做 `-40001` 换算。
4. **功能码16写入**：PLC可使用功能码16（0x10）一次性写入 `40001` ~ `40003` 等多个请求值，上位机NModbus库可正常解析。
5. 建议PLC程序中，对请求信号的置位加入防抖延时（建议100ms），避免机器人抖动导致误触发。
6. **寄存器使用说明**：
   - `40001`：PLC写入扫码请求，上位机读取
   - `40002`：PLC写入上相机拍照请求（点位编号），上位机读取
   - `40003`：PLC写入下相机拍照请求（点位编号），上位机读取
   - `40004`：上位机写入扫码结果，PLC读取
   - `40005`：上位机写入上相机拍照结果，PLC读取
   - `40006`：上位机写入下相机拍照结果，PLC读取
   - `40007` ~ `40011`：上位机写入型号字符串（最多10字符），PLC读取
7. **字符串结束符**：PLC读取型号时，以 `0x00` 作为字符串结束标志，0x00之后的字节忽略。
8. **扩展预留**：若后续型号长度超过10个字符，从 `40012` 开始向后扩展，不影响已有地址。

### 5.5.7 上位机代码示例（C#）

**读取PLC请求**

```csharp
// 读取扫码请求（40001）
ushort[] scanReq = master.ReadHoldingRegisters(40001, 1);
bool isScanRequested = scanReq[0] == 1;

// 读取上相机拍照请求（40002）
ushort[] camUpReq = master.ReadHoldingRegisters(40002, 1);
int camUpPoint = camUpReq[0];  // 0=无请求，>0=点位编号

// 读取下相机拍照请求（40003）
ushort[] camDownReq = master.ReadHoldingRegisters(40003, 1);
int camDownPoint = camDownReq[0];  // 0=无请求，>0=点位编号
```

**写入扫码结果（40004）**

```csharp
// 扫码OK
master.WriteSingleRegister(40004, 1);
// 扫码NG
master.WriteSingleRegister(40004, 2);
// 复位
master.WriteSingleRegister(40004, 0);
```

**写入拍照结果（40005 / 40006）**

```csharp
// 上相机OK
master.WriteSingleRegister(40005, 1);
// 上相机NG
master.WriteSingleRegister(40005, 2);
// 下相机OK
master.WriteSingleRegister(40006, 1);
// 下相机NG
master.WriteSingleRegister(40006, 2);
// 复位
master.WriteSingleRegister(40005, 0);
master.WriteSingleRegister(40006, 0);
```

**写入产品型号字符串（40007~40011）**

```csharp
/// <summary>
/// 将产品型号字符串写入 40007~40011（最多10个字符，ASCII编码）
/// </summary>
public void WriteProductModel(string model)
{
    byte[] bytes = new byte[10];
    byte[] modelBytes = Encoding.ASCII.GetBytes(model);
    int len = Math.Min(modelBytes.Length, 10);
    Array.Copy(modelBytes, bytes, len);
    // 末尾自动补0（已初始化全0）

    List<ushort> registers = new List<ushort>();
    for (int i = 0; i < 10; i += 2)
    {
        ushort value = (ushort)((bytes[i] << 8) | bytes[i + 1]);
        registers.Add(value);
    }

    master.WriteMultipleRegisters(40007, registers.ToArray());
}

// 调用示例：型号 "Z1212"
WriteProductModel("Z1212");
// 写入后：
// 40007 = 0x5A31 ('Z','1')
// 40008 = 0x3231 ('2','1')
// 40009 = 0x3200 ('2','\0')
// 40010~40011 = 0x0000
```

**PLC侧读取型号字符串（参考）**

```csharp
// PLC读取 40007~40011 共5个寄存器
ushort[] data = master.ReadHoldingRegisters(40007, 5);

// 转换为10字节
byte[] bytes = new byte[10];
for (int i = 0; i < 5; i++)
{
    bytes[i * 2] = (byte)(data[i] >> 8);
    bytes[i * 2 + 1] = (byte)(data[i] & 0xFF);
}

// 截取到第一个 '\0' 结束
int end = Array.IndexOf(bytes, (byte)0);
if (end < 0) end = bytes.Length;
string model = Encoding.ASCII.GetString(bytes, 0, end);
```

## 7.1 扫码枪触发指令细节（重要）

| 项 | 值 |
| --- | --- |
| 通讯方式 | 以太网 TCP/IP 无协议（上位机作 TCP 客户端，扫码枪作服务器） |
